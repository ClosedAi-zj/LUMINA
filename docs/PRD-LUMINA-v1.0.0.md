## 1. 产品目标与定位

**一句话**：为风光 / 建筑摄影师打造的 Windows 桌面一站式工作台 —— 素材库 → 精选 → 修图 → 交付全流程不换工具，目录即资产、永不锁库。

**三条差异化**（对应 11 帧「独有功能」，每条都必须在 v1.0.0 可演示）：

| # | 差异化 | 对标 PS/LR 的短板 | v1.0.0 验证方式 |
|---|---|---|---|
| D1 | **参数即文件 · 开放 XMP**：所有编辑写 sidecar，目录拷走即带走全部修改 | .lrcat 私有库 + 2026-04 目录损坏事故 | round-trip 幂等测试 + 他方字段字节不变测试（见 §7.2） |
| D2 | **数据完整性透明**：缺失 / 校验失败显式告知，根治 LR 静默吃掉 421 张（2.31%） | LR `errorMessage=0` 的静默缺失 | 人为制造缺失 / 篡改文件，UI 必须红点 + 清单，零静默 |
| D3 | **延时全链路内置**：RAW 序列去闪 + Holy Grail + 渲染队列，不需 LRTimelapse 中转 | LR 需外挂 LRTimelapse | 480 帧模拟序列走通「分析 → 关键帧 → 渲染输出」 |

**本轮范围决策（已拍板，不得推翻）**：交付形态 = C++17 引擎 + Electron/TS UI 混合架构（严格按路线图第四节）；v1.0.0 = **全模块闭环**——界面与交互全部实现，业务逻辑真实可跑。

## 3. 产品红线（任何版本不得违反，逐条给出验证方法）

| # | 红线 | 如何验证（可观察、可测试） |
|---|---|---|
| R1 | **不锁库**：编辑参数只写开放 XMP sidecar（`crs:` 标准 + `lumina:` 扩展），原片字节永不改写 | ① round-trip：写→读→写字节稳定（幂等）；② 不污染：对含 `lrt:` 样本写入 lumina: 字段后，其余字段逐字节不变；③ 全库文件 MD5 在编辑前后不变；④ 把整个目录拷到新路径重新打开，全部编辑参数仍在 |
| R2 | **非破坏性一切**：虚拟副本 / 快照 / 历史三层，任何操作可回退 | ① 任意滑块操作后历史栈可逐级回退到「导入原状」；② 虚拟副本 A/B 参数互不影响；③ 快照恢复后继续编辑不产生脏状态 |
| R3 | **文件完整性透明**：导入即校验，缺失 / 校验失败必须显式告知 | ① 人为移走 1 个文件 → 存储健康红点 + 清单条目，不得静默；② 篡改 1 个文件使 MD5 不符 → 进隔离视图并提供「从备份恢复」；③ 整夹不可读时导入向导给三选项（重定位 / 孤儿 / 衍生件回填），绝不允许静默跳过 |
| R4 | **NAS 可用性**：缩略图与预览常驻本地 SSD，原片按需拉取；离线可浏览、可管理、不可修 | ① 断开原片盘后：网格缩略图仍完整可浏览、可筛选 / 评分 / 精选；② 进入修图台时明确提示「原片离线」并禁用导出全质量操作；③ 重连后无需重新导入即恢复 |
| R5 | **照片观察区固定 #08090B**：查看器 / 地图 / 延时画面不随浅色主题翻转 | ① 切浅色主题后，修图台画面区 / 地图 / 延时预览的背景像素值仍为 `#08090B`（自动化像素断言）；② 令牌来源唯一：仅 `--Lumina-Tokens-viewer`，任何组件不得硬编码 |

## 4. 用户故事（按 9 模块，每条带验收标准）

### ① 素材库（浏览 / 筛选 / 搜索）
- 作为摄影师，我希望 18,192 张照片在网格里流畅滚动，以便快速找回某天的拍摄。
  **验收**：连续滚动 60s 实测 ≥30fps；滚动中空白帧不超过 1 行；缩略图 120–320px 连续缩放不崩。
- 作为摄影师，我希望按文件夹树 + 拍摄时间轴浏览，以便沿用我"日期文件夹"的既有习惯。
  **验收**：默认视图为文件夹树 + 时间线；5 根目录可折叠；点击时间轴某月柱跳到该月首张并高亮当前月。
- 作为摄影师，我希望按地点 / 相机 / 镜头 / 格式 / 评分 / 时间段组合筛选，以便缩小候选范围。
  **验收**：多维 AND 生效；生效维度以 chips 显示在 GridHeader 下方且单个可移除；筛选后计数实时更新。
- 作为摄影师，我希望在顶栏搜索框按文件名 / 地点 / 日期快速检索，以便不翻文件夹直接定位。
  **验收**：防抖 200ms 后发起查询，结果响应 < 100ms；空结果显示「无匹配 · 清除筛选」。

### ② 导入向导
- 作为摄影师，我希望插上 SD 卡就自动被检测并给出摘要，以便导入前心中有数。
  **验收**：SD 卡 / 文件夹双来源卡可选；点击即异步扫描；摘要卡展示总数、体积、格式分布、重复数（与库内 MD5 比对）、伴随 JPG 统计；读失败的文件标红计入摘要。
- 作为摄影师，我希望导入时自动做 NAS 双备份 + MD5 校验，以便数据从我手里这一刻起就是安全的。
  **验收**：备份与校验开关默认开；目标剩余空间 < 需求 110% 时黄条预警；导入完成逐文件校验，失败进存储健康异常队列。
- 作为摄影师，我希望导入失败的文件不中断整批，以便一次导入几十 GB 不被单张卡死。
  **验收**：执行态显示总进度 / 当前文件 / 速率 / 预计剩余；单文件失败进失败清单；完成弹「成功 N · 跳过重复 N · 失败 N」。
- 作为摄影师，我希望源文件夹整体丢失时给我明确选项，以便像 LR 那样静默吞掉文件的惨剧不发生。
  **验收**：整夹不可读时出现「重定位文件夹 / 跳过并记入孤儿清单 / 衍生件回填」三选项。

### ③ 修图台（快速 / 专业双模式）
- 作为摄影师，我希望在快速模式用预设 + 基本滑块 + 局部蒙版快速出片，以便批量照片不过夜。
  **验收**：预设列（余晖斜刺 / 苍穹·山岚 / 深夜深色 / 建筑·透视 / 日出金顶等）一键套用；基本 6 滑块 + 色调曲线 + 渐变 / 径向 / 画笔三件套可用；参数 500ms 防抖写入 XMP 且 UI 出「参数已写入 XMP」状态。
- 作为摄影师，我希望切到专业模式使用调整图层栈 / 点曲线 / 混色器 / 颜色分级 / 细节 / 光学 / 校准 / 范围蒙版，以便精细控制。
  **验收**：图层栈有序、每层可开关 / 调不透明度 / 改混合模式，并持久化到 `lumina:AdjustmentStack`；直方图 / 前后对比（Before·2 已保存）可用；历史步骤逐级可回退。
- 作为摄影师，我希望把一套参数同步到同组序列，以便延时 / 连拍组统一调色。
  **验收**：「同步设置到所选」「同步到序列」生效后，所选 / 序列内照片的 sidecar 参数一致；胶片条显示「N 张已同步参数」。

### ④ 精选模式
- 作为摄影师，我希望纯键盘流完成淘汰（X）/ 置优（P）/ 评分（0-5）/ 对比（Enter）/ 全屏（F）/ 放大镜（Caps），以便一小时过完一天的拍摄量。
  **验收**：六个键全部生效且底部快捷键条与实际行为一致；淘汰态叠加 #0C0D10 @50%；今日已挑计数实时更新。
- 作为摄影师，我希望规则自动把 ≥4★ 且带视觉标准的照片晋级精选集，以便把时间花在刀刃上。
  **验收**：自动晋级规则可开关；晋级结果进入指定精选集；精选进度（如 24/68）与进度条实时更新。
- 作为摄影师，我希望批量置优 / 同步参数到同筛选 / 清除已拒绝，以便收尾动作不重复劳动。

### ⑤ 地图模块
- 作为摄影师，我希望在地图上看到地点集群和拍摄分布，以便按地点回忆与检索。
  **验收**：地点钉带计数、缩放时聚合 / 展开；左侧地点列表带计数与「仅显示已定位」开关；点击钉出右侧详情卡（坐标 / 海拔 / 数量 / 时间跨度 / 打开文件夹 / 将此地点收藏）。
- 作为摄影师，我希望无 GPS 的照片能反向定位并写回，以便老照片也能按地点组织。
  **验收**：选中照片 → 拖放 / 指定地点 → 写入 sidecar（**不碰原片 EXIF**，默认写 sidecar 的 exif: 命名空间，见 §9-Q1）；写入后网格项出现 GPS 图钉。

### ⑥ 延时工作台
- 作为摄影师，我希望 RAW 序列自动识别成组并做去闪分析，以便不必再开 LRTimelapse。
  **验收**：序列列表（序列名 / 帧数 / 状态）；去闪分析完成显示量化结果（如「亮度提升 12.3%」）；预览播放器支持帧级拖动与播放。
- 作为摄影师，我希望编辑 Holy Grail 关键帧和曝光过渡曲线，以便日转夜场景曝光平滑。
  **验收**：关键帧表（帧号 / 曝光补偿 / 色温）可增删改；曲线上关键帧点可拖动微调；关键帧持久化到 `lumina:ExposureRamp`（尽力兼容 `lrt:`）。
- 作为摄影师，我希望把 480 帧渲染成 4K 成片并排队管理，以便一条龙出片。
  **验收**：分辨率 / 帧率 / 编码可选；渲染队列显示进度百分比与预估剩余；产物落盘可播放（编码降级见 §8.7）。

### ⑦ 风光专项
- 作为摄影师，我希望 7 张包围直接合成 HDR（自动对齐 + 曝光合并 + 鬼影消除），以便不必开外部合成软件。
  **验收**：选择包围组 → 合成 → 输出结果可进修图台继续编辑；合成过程有进度，失败显式报错。
- 作为摄影师，我希望经典降噪（NLM + 亮度蒙版）提升高感画质，以便夜景不用等 AI 降噪。
- 作为产品要求，v1.1 / v1.2 功能卡（全景拼接 / 景深堆栈 / AI 降噪）在 12 帧版式上以**禁用态 + 版本 chip** 呈现，位置预留到期即填。

### ⑧ 导出与交付（含 Web 画廊）
- 作为摄影师，我希望按预设导出 JPG / TIFF / PNG / PSD（带图层）+ 水印 + 命名模板，以便一次配置反复使用。
  **验收**：四种格式可选（PSD 带图层）；水印开关 / 位置（右下 · 88%）/ 大小滑杆生效；导出结果命名符合模板。
- 作为摄影师，我希望把画册一键发布成带密码的 Web 画廊给客户，以便交付不依赖网盘。
  **验收**：作品集画册（自动排版 / 拖拽排序）→「发布到 Web 画廊」生成访问链接 + 密码；30 天有效期可撤回；画廊页含 hero、计数条（张数 / 已收藏 / 浏览完成率 / 有效期）、筛选（全部 / 已收藏 / 未收藏）、客户收藏标记、交付下载区（Web 质量 JPG + 印刷质量 TIFF·AdobeRGB 密码 + 下载全部）。
- 作为摄影师，我希望客户的收藏动作回传给我，以便二轮精选有依据。
  **验收**：客户点收藏 → 摄影师端看到「8 已收藏」计数与标记分布（本地回传路径见 §8.6）。

### ⑨ 存储健康
- 作为摄影师，我希望一眼看到全库校验 / 缺失 / 备份 / MD5 四项状态，以便数据风险不再靠运气。
  **验收**：大数字行「已校验 N / 全库 N」；缺失文件（实时监测）/ NAS 双备份（状态 + 时间）/ MD5 校验（百分比 + 后台进行）四行齐备；任一非正常即出红点进异常队列。
- 作为摄影师，我希望每个缺失 / 损坏文件都有处理出口，以便异常清零。
  **验收**：缺失清单三操作（重定位 / 标记孤儿 / 衍生件回填）走通；校验失败进隔离视图且有「从 NAS 备份恢复」直达按钮；**任何异常不得被吞掉**（对应 R3）。

## 6. 关键交互约定

### 6.1 修图快速 vs 专业模式切换
- 入口：修图台顶栏「快速 | 专业 Pro」分段控件（10 帧）。
- 两模式**共享同一参数模型与同一份 XMP sidecar**，切换只改控件呈现，禁止出现两套参数状态。
- 切换不触发重新解码 / 画面闪黑；切换后滑块位置、图层栈、历史栈原样保留。
- 快速模式隐藏图层栈 / 混色器 / 校准等专业组；专业模式全量呈现。
- 预设在两模式通用（预设 = 参数集合，写入 sidecar）。

### 6.2 深浅双主题规则
- 深色默认；浅色按路线图随 M4 落地（+20% 工期已计入排期）。
- 切换机制：根元素 `data-theme="Light"`，全部颜色来自 design-tokens.css 变量，**禁止组件内硬编码颜色**。
- **照片观察区（修图台画面 / 地图 / 延时预览）恒用 `--Lumina-Tokens-viewer`（#08090B），不随主题翻转**（R5）。
- 新组件默认继承令牌双模式；评审时以「切主题无残色」为通过线。

## 7. 数据与非功能要求

### 7.1 性能基线（硬指标，进入验收）

| 指标 | 基线 | 验证方式 |
|---|---|---|
| 网格滚动 | 18,192 张 ≥30fps，空白帧 ≤1 行 | 模拟图库全量 + 性能面板实测 |
| 搜索响应 | < 100ms（防抖 200ms 后计时） | SQLite 3.54.1 + `-DSQLITE_ENABLE_FTS5`，18,192 条索引；FTS5 查询计时埋点 |
| 导入吞吐 | ≥ 80MB/s（本地 SSD） | 导入执行态速率显示 + 日志 |
| XMP 落盘 | 编辑停止 500ms 防抖落盘；关图 / 切图强制 flush | 文件 mtime 监测 |
| 智能代理 | 代理缺失时同步解码并缓存，二次浏览命中缓存 | 二次滚动帧率对比 |

### 7.2 XMP 读写纪律（红线 R1 的实现口径，全文见 `specs/XMP-字段映射表.md`）
1. 标准优先：crs: 有的一律写 crs:，不私造；仅 PS/LR 没有的能力写 `lumina:`（带 `lumina:SchemaVersion`，从 1 起）。
2. 原片零写入：参数只进 sidecar；RAW 字节永不改动（含 GPS 反写——写 sidecar 而非 EXIF）。
3. 不改写他方字段：非 LUMINA 写入的字段（其他工具 / LRTimelapse `lrt:`）解析-修改-序列化保序保注释，逐字节保留；未知命名空间原样缓存、回写吐回。
4. 原子写：temp + rename；崩溃不得写坏 sidecar。
5. 冲突：sidecar mtime 变化 → 弹「文件已被其他工具修改」三选（重读 / 覆盖 / 另存）。
6. 迁移：启动扫描 SchemaVersion 分布，旧版本静默自动迁移并记录；ProcessVersion 高于引擎认知 → 提示「部分参数可能不显示」，绝不猜测丢弃。
7. **M1 出口必测五用例**（映射表 §9）：存量 sidecar 解析无丢失 / round-trip 幂等 / 不污染他方字段 / 外部修改检测 / 迁移器。

### 7.3 数据完整性要求
- 导入即 MD5 校验（默认开），失败进隔离视图 + 「从备份恢复」；校验进度百分比可见。
- 缺失检测实时化：文件系统事件 + 启动全量扫描兜底；任何缺失 / 损坏**必须显式告知**（R3），提示文案不得弱化为可忽略的小字。
- 备份：NAS 双备份（本轮替身为第二目录，见 §8.5），备份状态含最近成功时间。

### 8.2 RAW 解码：LibRaw 已就位（内嵌 JPEG 提取作为保留降级通道）

| 项 | 内容 |
|---|---|
| **默认方案（已就位）** | **LibRaw 0.21.4 真实全解码**：`D:/LUMINA/thirdparty/libraw/`，`lib/libraw.a` 已由 MinGW 编译产出（构建日志 EXIT=0，`raw-identify.exe` 等样例已生成）。链接参数基线：`-lraw -lws2_32 -lm`，编译宏 `-DLIBRAW_NOTHREADS` 可选。管线按路线图第四节：LibRaw 解 RW2 → 线性 RGB →（色彩管理，见 §8.3）→ GLSL 实时预览 |
| 待验证点（架构师） | ① CMake/Ninja 下链接静态库无符号缺失；② 用**模拟 RW2** 走通 `open → unpack → dcraw_process → 输出线性 RGB` 冒烟；③ 解码耗时进入 §7.1 性能基线实测 |
| **降级通道（保留）** | 若链接失败或 RW2 冒烟不通过：**RW2 内嵌 JPEG 预览提取**（RW2 容器内嵌全尺寸 / 缩略图 JPEG，可真实解析）作为快速预览像素来源；修图参数仍然真实计算并写入 XMP，预览用 GLSL 对参数做**逐项近似渲染**，UI 必须标注「预览近似 · 全质量渲染待 RAW 管线接入」 |
| **替换条件（明确）** | 降级 → 真实：**只需满足两项**: (a) `lib/libraw.a` 在引擎目标下链接通过；(b) 至少 1 张模拟 RW2 由 LibRaw 解出非空线性 RGB 像素。两项达成即切回真实管线（此时提取通道自动退位为「代理图」角色，架构层级不变：代理 → 全解码两级）。真实 → 降级：(a)(b) 任一不成立即回退，并在 README/UI 标注当前处于降级态 |
| 风险 | ⚠️ **最大风险点：模拟 RW2 不是真 RAW**——程序化生成的 RW2 必须满足 §8.4 的容器要求（合法 IFD + 真实 CFA 数据 + 内嵌 JPEG 预览），否则 LibRaw 只能"假装可用"，真实图库接入时会返工。次风险：近似渲染与真实解码观感不一致 → 色彩验收以 sidecar 参数值为准，预览观感不作为验收依据 |

### 8.4 模拟图库：程序化生成（元数据分布复刻真实基准）

| 项 | 内容 |
|---|---|
| 替身方案 | 内置**模拟图库生成器**（C++ + stb）：① 影像本体 = 程序化生成的风光 / 建筑占位图（渐变地形 + 噪声纹理 + 天空光效，非真实照片），用 `stb_image_write.h` 落 JPEG/PNG；② 元数据严格复刻调研基准：18,192 张（RW2 16,470 / JPG 1,387 / DNG 273 / ARW 15 / 视频 45 / PSD 1 / PNG 1）、5 根目录 79 文件夹按日期组织（2025-12 → 2026-08）、421 张缺失（RW2 417 + MP4 4，集中 7 个文件夹）、已调整 4,347 张其中 83.8% 含局部蒙版（3,639）、修复笔画 58、评分 2★ 1,365 / 3★ 1 / 4★ 57 / 5★ 0、GPS 137（0.75%）、白平衡 As Shot 14,310 / Custom 3,861、sidecar 分布复刻（延时组含 lrt: 结构）；③ 模拟 RW2 容器规格见下方加粗要求 |
| 真实方案 | 用户真实 512GB 图库子集 |
| 替换条件 | M1 出口验收时拿真实子集跑「导入 → 浏览 → 搜索 → 健康扫描」（任务书出口标准）；替换前模拟图库**就是**性能与扫描验收负载 |
| 风险 | 真实 RW2 的解码兼容性问题在替身阶段暴露不出来 → XMP 读写验证优先用真实 fixture：若盘上 2,052 个真实 LR/LRTimelapse sidecar 可访问（不含图像本体），直接作为读写测试集；不可访问则程序化生成同分布 sidecar，并把「真实 sidecar 回归」列入接入真实图库时的必测项 |

> ⚠️ **模拟 RW2 的容器要求（LibRaw 能否真实跑通的命门，工程师务必照此实现）**
> 每个模拟 RW2 必须是**结构合法的 RW2/TIFF 容器**：① 合法 IFD + Panasonic MakeNote + 必需标签（ImageWidth/Height、BitsPerSample、CFAPattern、BlackLevel、WhiteLevel、CameraIFD 等）；② **真实 CFA（Bayer）数据区**——由程序化生成的灰度/色彩图下采样为单通道 Bayer 阵列并写入 Strip；③ 同时**内嵌全尺寸 JPEG 预览 + 缩略图**，供降级通道（§8.2）与代理优先渲染使用。
> **验收分档**：L1（要求达到）= LibRaw `open + unpack + dcraw_process` 真实解出非空线性 RGB；L2（不可达时的兜底）= 仅内嵌 JPEG 可提取。若整批模拟 RW2 无法达到 L1，必须在验收报告中显式标注「本轮 RAW 管线验证强度 = L2」，并在真实图库接入时补 L1 回归。
> 占位图像素可用 `stb_image_write.h` 直接写 JPEG/PNG（用于伴随 JPG、Web 画廊产物、导出结果），本体由 C++ 生成器 + stb 产出，无需外部素材。

### 8.9 汇总：替身不影响「真实可跑」的底线

- 所有替身均满足：界面与交互完整、状态机真实、数据落盘真实（sidecar / SQLite / 文件产物）、异常路径真实可达。
- 禁止出现：假按钮、写死返回值的假异步、永远成功的假校验。凡替身必在 UI 或产物上有可见标记（如「预览近似」「本地预览级」）。
- **本轮替身清单（仅此 6 项，其余全部真实实现）**：色彩管理 sRGB 直通（§8.3）、模拟图库（§8.4）、NAS 第二目录（§8.5）、Web 画廊本地静态（§8.6）、视频编码途径（§8.7）、地图程序化底图（§8.8）。
- **非替身（依赖已真实就位，照真实口径实现）**：SQLite + FTS5 检索（§8.0）、LibRaw 全解码（§8.2 默认路径，降级通道仅在验证失败时启用）、stb 图像读写、引擎 stdio JSON-RPC 进程架构（§8.1 为既定架构决策而非替身）。
- 每次依赖项 / 工具链状态变化，同步更新 §8.0 状态表，避免出现「文档说缺失、实际已就位」的错配。
