## 1. 版本定位与变更根因

### 1.1 一句话定位

**v1.2.0 = 先修裁判，再谈功能。** 用一个参数节点链求值器（NodeGraph）取代三套互不相等的渲染实现，把管线顺序、色彩位深、蒙版数学、几何与镜头阶段一次性做对，让「预览 = 导出」成为可机器验证的事实，然后才允许 PSD 出口与打印打样上线。

### 1.2 作废旧口径的根因（三条结构性缺陷）

| # | 缺陷 | 事实（代码级） | 产品定性 |
|---|---|---|---|
| A | **预览 ≠ 导出** | 导出链路只应用 **27 / 93** 个参数叶（`engine/src/export/exporter.cpp:719-742` 仅读 `exposure/contrast/saturation` + HSL 8 带）；GPU 预览 **39 / 93**（`app/src/modules/develop/webgl/renderer.ts:48-69` + `shaders.ts`）。高光、阴影、白/黑、白平衡、曲线、清晰度、去雾、蒙版、裁剪、镜头校正、暗角、颗粒、校准在导出时**逐项静默丢弃** | **在线正确性缺陷**，不是缺功能。用户调完图导出得到一张「只有基础四项」的图且无任何提示 = 交付废片。直接违反红线 R3（结果必须显式告知），必须一次修完，不设止血版本 |
| B | **12 类假控件** | 参数能存、UI 能调、像素不动：纹理、分通道曲线、参数曲线、颜色分级 8 项、校准 7 项、锐化/NR 7 项、镜头配置、裁剪/透视 13 项、暗角中点、颗粒大小、范围蒙版（可切换但回落画笔分支静默失效）、调整图层栈 | 比缺功能更坏：**让用户以为自己在精修**。属于产品诚信问题，与 R7 一起作为上线闸门 |
| C | **8-bit sRGB 全链路天花板** | `engine/src/raw/raw_decoder.cpp:58-59` 写死 `output_color=1 / output_bps=8`；`imaging::Image` 为 `uint8_t[3]`；无线性工作空间、无 ICC | 数学上「对标 Lightroom / Photoshop」不成立。高光/曝光在 gamma 空间运算必然错，必须先建 16bit 线性地基再谈参数覆盖 |

补充事实（决定架构形态）：**存在三套互不相等、无对拍测试的渲染实现** —— WebGL 预览（`app/src/modules/develop/webgl/`）、Canvas CPU 回退（`cpu-render.ts`）、引擎导出（`exporter.cpp`）。三者不共享参数结构，「口径靠人记」，这是缺陷 A/B 的共同土壤。

### 1.3 用户已拍板的四项前提（本 PRD 的上位约束，不得改动）

| # | 决策 | 对 PRD 的约束 |
|---|---|---|
| D1 | **不发 v1.1.2 止血**，缺陷并入 v1.2.0 一次解决 | 不设中间版本；v1.2.0 出口必须一次性满足 R7 全绿，不接受「先修一半」 |
| D2 | 内核升级为**参数节点链 NodeGraph**，粒度 = **参数组**（约 8 类节点 + 可选蒙版 + 可选混合） | 8 类节点 = 修图右栏 8 组面板（1:1），UI 面板数不得多于或少于节点类型数 |
| D3 | 色彩科学走**自有色彩科学**路线：**不追 Adobe Standard**；验收 = 对相机内置 JPEG **中位 ΔE ≤ 3**，语料以松下 S5M2（占用户图库 92.2%）为准 | 对外表述统一为「自有色彩科学」，禁止「像 LR / 等同 ACR」；验收只认 ΔE 数值（§6） |
| D4 | LibRaw 维持**静态链接** + 补齐 LGPL-2.1 §6 可重链接材料；对外**不宣传 clean-room** | 分发物必须含 relink 材料；文案与发布说明不得出现 clean-room 主张 |

### 1.4 本版与基线 PRD 的关系

- 保留并沿用：素材库 / 导入 / 精选 / 地图 / 延时 / 存储健康 / Web 画廊的全部已冻结范围与验收口径（基线 PRD 中未被本文覆盖的条目继续有效）。

- 失效：旧 PRD 的 F5 星空规划（下沉 v1.3）、F8 移动端（本版砍掉）。

## 2. 目标用户与场景

| 项 | 值 | 对本版需求的直接含义 |
|---|---|---|
| 目标用户 | 风光 / 建筑摄影师（延时 + 精修双工作流） | 强依赖高光/阴影恢复、白平衡、渐变蒙版、透视校正、批量一致性 |

| 元数据实况 | 评分覆盖率 7.8%（5★=0）、GPS 0.75%、关键词 0 | 不以元数据重度使用为设计前提（沿用基线） |
| 核心场景 | ① 一天拍 800 张 → 精选 → 批量套预设 → 精修 8 张 → 交付客户；② 同一机位延时序列 → 全序列统一调色；③ 建筑竖拍 → 透视校正 → 打印打样 | R7 优先保障「批量参数一致性」与「导出即所见」 |

## 3. 范围冻结

### 3.1 里程碑与范围（人日为量级估算 ±40%，来源 KICKOFF §5.1）

| ID | 里程碑 | 范围（必须做，无省略项） | 出口条件（可判定） | 人日 |
|---|---|---|---|---:|
| **M0** | 地基 | ① `imaging::Image` 升 16bit（half-float 与 uint16 之间**定一种并写死**）；② 线性工作空间建立（sRGB 传输函数只在显示末端施加）；③ RAW 输出改 16bit + 线性（`raw_decoder.cpp` 的 `output_bps=8 / output_color=sRGB` 两处必须消失）；④ CPU oracle 骨架（同一 Plan 的 CPU 参考实现 + 差异统计器） | 同一参数集在 CPU 与 GPU 上 **mean\|Δ\| < 0.5、max ≤ 3 LSB**（1024×683 测试图，10 组参数组合逐组达标） | 35 |
| **M1** | 求值器统一 | ① NodeGraph 数据模型落地（`lumina:NodeGraph`）；② 8 类节点（basic / curve / color / detail / lens / geometry / effects / calibration）+ 可选蒙版 + 可选混合；③ **销毁三套实现**，收敛为一套参数结构 + 一套算子表；④ `crs:` 投影层保持 LR 兼容读写；⑤ 假控件 12 类全部拆除（附录 A） | **93 个参数叶逐个「预览生效 / 导出生效 / 有像素断言」三连通过**（判据见 §5） | 45 |
| **M2** | LR 闭环 | ① 管线顺序重排：白平衡置首（作用于线性原始数据）；② 几何阶段（裁剪/拉直/透视 13 项，resize 归几何阶段）；③ 镜头校正阶段（参数化，不内置 Adobe LCP）；④ 蒙版数学正确化 + 槽位不限 + 范围蒙版落地；⑤ 曲线全谱（复合/分通道/参数）；⑥ 库内 `develop_settings` 参数缓存；⑦ history 落盘 | ① 色彩科学 ΔE 中位 ≤ 3（§6）；② 12 蒙版预览与参考实现 mean\|Δ\| ≤ 2/255 且范围蒙版真的改变像素；③ 重启后 history 与库内参数完整（抽 20 张逐项比对）；④ 管线顺序断言在位（20 阶段顺序表，WB 为第 1 位） | 60 |
| **M3** | PS 出口 | ① PSD 写出（图层 + 每层 `lumina:` 快照 + 未知 tagged block 原样回写）；② PSD 内嵌 merged composite 对拍；③ 无快照时降级为像素层并**显式告知** | ① Photoshop 2026 能打开我们导出的 PSD 且无修复警告；② merged composite 对拍地板值 ≥ **190/258** 用例（只许升不许降）；③ 未知 tagged block 往返字节一致 | 35 |
| **M4** | 色彩与打印 | ① LCMS2 接入内核；② 嵌入 AdobeRGB ICC 且往返无损；③ 软打样（目标 profile 渲染 + ΔE 报告） | ① ICC 往返无损（同一图像 transform 去回 mean\|Δ\| = 0、max ≤ 1 LSB）；② 软打样 ΔE00 中位 ≤ 2.0、95 分位 ≤ 4.0（10 张样本） | 29 |

**合计 204 人日**（2 人并行约 4 个月）。若追加修复画笔 + 变换精修 + 文字系统 → 265 人日（本版不含，见 §3.3）。

### 3.2 原 v1.2.0 八项处置（逐一给结论，不留模糊项）

### 3.4 需求编号体系

需求 ID 规则：`M{里程碑}-{序号}`（如 `M2-04`）；追加包 `P1-{序号}`；红线 `R{1..7}`。**每个 ID 必须有验收口径**；无验收口径的 ID 不允许进入开发。

## 4. 需求与验收口径（按里程碑）

> 验收通则：每条需求的验收必须落在**可执行产物**上（CI 用例 / 报告文件 / 截图 / 比对 JSON），不接受口头确认。凡「看起来对」的表述一律视为未验收。

### M0 地基（35 人日）

| ID | 需求 | 验收口径（可判定） | 证据产物 |
|---|---|---|---|
| M0-01 | 内部像素表示升级为 16bit（half-float 与 uint16 **定一种并写死**，不允许混用） | 全链路无 `uint8_t[3]` 图像缓冲（静态检查 0 命中）；16bit 图在接近白处 max ≥ 60000（uint16）或 ≥ 0.9（half）不过曝；同一图 8bit 与 16bit 往返 mean\|Δ\| ≤ 0.5 LSB(16bit) | `m0-bitdepth-report.json` + 静态检查日志 |
| M0-02 | 建立线性工作空间：所有像素运算在线性域，sRGB 传输函数只在显示末端施加 | 曝光 +1EV 在 16bit 线性域输出 = 输入 × 2（±1 LSB）；同一操作在 gamma 域执行的反例用例**必须失败**（证明测试有鉴别力）；18% 灰经 +1EV 后编码值落在预期窗口 | `m0-linear-proof.json`（含反例） |

| M0-04 | CPU oracle 骨架：同一 Plan 的 CPU 参考实现 + 差异统计器（mean\|Δ\| / max LSB / P99） | 10 组参数组合（覆盖 basic/curve/color/detail/effects）在 CPU 与 GPU 各渲染 1024×683，**逐组 mean\|Δ\| < 0.5 且 max ≤ 3 LSB**；统计器输出 JSON 可被 CI 读取 | `m0-oracle-parity.json` |
| M0-05 | 93 参数叶注册表（`param-leaves.json`：叶名 / crs: 映射 / 定义域 / 所属节点 / 默认值） | 条目数 = **93**（分类计数见 §5.3）；CI 解析该表并断言每个叶在预览与导出的算子表中**存在引用**；M0 阶段允许「引用但未实现」并列入待办，M1 起改为强制三连 | `param-leaves.json` + CI 存在性报告 |

## 5. 红线 R7 · 所见即所得（新增，最高优先级）

### 5.1 定义

> **R7**：任何 UI 上可见、可调节的参数，必须**同时**满足三格：**① 预览生效 ② 导出生效 ③ 有像素断言**。
> 三格缺一格 = 该参数**未完成**，不得计入交付、不得出现在发布说明、不允许上线。

R7 是 v1.2.0 的**验收总闸门**。它把缺陷 A（预览≠导出）与缺陷 B（假控件）变成不可再发生的结构约束：没有三格证据，参数就不允许出现在 UI 上。

### 5.2 可执行验收方法：93 叶三连矩阵

**第 0 步 · 注册表**：`param-leaves.json` 列出 93 叶，每叶含 `leaf / node / crsField / domain / default`（M0-05 交付）。

**第 1 步 · 单叶像素断言（第 3 格）**：对每叶在定义域取三点（`min / default / max`；枚举型取全部值；曲线型取 3 组形状），相对「全默认基线」渲染，断言：

| 叶类型 | 断言 |
|---|---|
| 全局标量（曝光/对比/高光/阴影/白/黑/色温/色调/饱和/自然饱和/去雾/清晰度/纹理/颗粒…） | 非零差异像素占比 ≥ 0.5%，且方向正确（如高光 -100 时高亮区均值下降 ≥ 5/255） |
| 通道 / 色相类（HSL 24、校准 7、颜色分级 8） | 目标色相区（±30°）变化 ≥ 阈值，非目标区变化 ≤ 1 LSB（证明选择性真实存在） |
| 曲线类（复合/分通道/参数 15 项） | 复合曲线影响 RGB 三通道；分通道仅影响对应通道（其余 ≤ 1 LSB）；参数曲线 4 段各自产生分段差异 |
| 几何类（裁剪/透视 13 项） | 几何断言（尺寸 / 四角坐标 / 位移方向），不要求像素统计 |
| 局部类（蒙版容器 + 蒙版内 9 项局部参数） | 蒙版区内变化 ≥ 阈值，**区外 ≤ 1 LSB**（蒙版数学正确性的核心判据） |
| 全部叶的负向断言 | 该叶 = 默认值时输出与全默认基线逐像素相等（max\|Δ\| = 0），证明无副作用 |

**第 2 步 · 预览 vs 导出（第 1+2 格）**：对每叶同样三点，分别在 GPU 预览、CPU 回退、引擎导出三端渲染，断言 **mean\|Δ\| < 0.5 且 max ≤ 3 LSB**。

**第 3 步 · 汇总产物**（CI 输出，格式固定）：

```json
{ "commit": "...", "totalLeaves": 93,
  "leaves": [ { "leaf": "highlights", "preview": "pass", "export": "pass",
                "pixelAssert": "pass", "meanAbsDiff": 0.12, "maxLsb": 2,
                "evidence": "artifacts/highlights/*.png" } ] }
```

**第 4 步 · 出口判定**：三格全 pass 的叶数 = **93** 才允许 M1 出口与 v1.2.0 发布；任一叶 fail → 该叶从 UI 撤下或置灰标注「未支持」后重跑全量。

### 5.3 93 叶分类计数（可与注册表核对）

| 分类 | 叶数 | 内容 |
|---|---:|---|
| 基础 | 14 | 白平衡模式 / 色温 / 色调、曝光、对比、高光、阴影、白、黑、清晰度、纹理、去雾、自然饱和、饱和 |
| 曲线 | 4 | 复合 RGB、R、G、B |
| 参数曲线 | 7 | 高光 / 亮调 / 暗调 / 阴影 + 阴影分界 / 中间分界 / 高光分界 |

### 5.4 三条机器判据（写进 CI）

1. **覆盖率**：93/93 叶三连通过，逐叶记录在 CI 产物里；
2. **等价性**：CPU vs GPU（以及预览 vs 导出）mean\|Δ\| < 0.5、max ≤ 3 LSB；
3. **PSD 合成对拍**：以 PSD 内嵌 merged composite 为 oracle，地板值 190/258 只许升不许降。

> 地板值语义默认按「通过用例数 / 总用例数」计（单用例判据见 M3-02）。若架构师按 R3 报告给出更严定义（如得分制），**取更严者执行**并在 CI 产物注明口径版本。

## 6. 色彩科学验收（ΔE ≤ 3，禁用「看起来像」）

### 6.1 路线与表述纪律

- 路线：**自有色彩科学**（不追 Adobe Standard，不分发 Adobe DCP）。
- 对外表述统一为「LUMINA 自有色彩科学」，**禁止**「等同 Camera Raw / 复刻 Adobe Standard / 像 LR」；发布说明只允许出现可测数值（ΔE 中位数 + 样本量）。

### 6.2 测量方法（可复现）

| 项 | 规定 |
|---|---|
| 语料 | 松下 S5M2 的 RAW + 同机同场景**相机内置 JPEG**（标准照片风格）配对，≥ **30 对**；覆盖 ISO 100 / 800 / 3200 / 6400、日光 / 阴天 / 白炽灯、风光 / 建筑 / 夜景各 ≥ 6 对 |
| 渲染口径 | RAW 经 LUMINA 默认管线（相机 WB + 自有色彩科学 + 默认 tone curve + 锐化关闭）输出 sRGB 8bit；与相机 JPEG 同尺寸（参考图双三次缩放对齐） |
| 采样 | 排除最亮 1% 与最暗 1% 像素（截断区）；排除图像边缘 2px 与水印/文字区；每对随机取 20 万像素点（固定随机种子，可复现） |
| 度量 | CIEDE2000（Lab 由 sRGB D65 转换） |
| 判据 | **中位 ΔE00 ≤ 3.0**；90 分位 ≤ 5.0；任一张图的中位不得 > 8.0 |
| 产物 | `color-science-{version}.json`：逐图中位 / 90 分位 / 采样数 + 汇总箱线图 |

### 6.3 失败处理（不许含糊）

| 情形 | 处理 |
|---|---|
| 中位 ≤ 3.0 且 90 分位 ≤ 5.0 | **通过**，可发布 |
| 中位 ≤ 3.0 但 90 分位 ∈ (5.0, 6.5] | **条件通过**：需主理人书面确认 + 发布说明标注「高饱和场景偏差偏大」，差额样本列入 v1.3 改进清单 |
| 中位 ∈ (3.0, 5.0] | **不通过**：M2 不出口；允许最多 2 轮参数调优，仍不达标 → 上报用户决策（降级承诺或延后发布） |
| 中位 > 5.0 | **不通过且不得对外宣称色彩达标**，该版本不得发布 |
| 任何「肉眼看着接近」但无数值证据 | **视为未验收** |

### 8.2 R1「不锁库」在 NodeGraph 内核下的保持方式（本版最容易走偏的一条）

| # | 规则 | 验收 |
|---|---|---|
| 1 | **XMP 是唯一真相源**。NodeGraph 的持久化真相 = sidecar 的 `crs:` + `lumina:` 字段；库内 `develop_settings` 只是**可重建缓存** | 删库缓存后由 sidecar 全量重建，参数逐条相等（M2-06） |
| 2 | **PSD 只做单向派生**。PSD 是出口物不是真相源；每层 `lumina:` 快照仅供回读参考，不参与主链路 | 改 sidecar 后重新导出 PSD 产物随之变化；不存在「改 PSD 回写 sidecar」的代码路径 |
| 3 | **禁止双写**。不允许参数同时以 sidecar 与库内为双真相；投影层（`crs:` ↔ NodeGraph）是唯一映射点，映射表版本化 | 静态检查：sidecar 写入路径唯一；映射表带 `mappingVersion` |
| 4 | **语义变更必须迁移 + 显式告知**。管线顺序重排会改变同一组参数的解释结果（尤其白平衡、曲线在非线性域的旧值） | SchemaVersion 1 → 2 迁移器；提供「旧解释 vs 新解释」差异报告供用户查看，不静默改观感 |
| 5 | 原片字节永不改写（GPS 反写仍写 sidecar `exif:`，沿用基线口径） | 全链路 MD5 三重校验，0 变更 |
