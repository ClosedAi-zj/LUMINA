## 1. 语义变化(为什么要做)

蒙版渲染语义两级升级:

1. **v2 composite → v3 独立 mask pass**(commit 054eb2c,T2.7):旧实现是末道 composite
   内联蒙版(display 域近似、仅 7 叶、6 槽截断);新实现为 tone 后 sharpen 前的独立 pass,
   引擎域逐式镜像 `mask_field.cpp`/`mask.cpp`,严格 `w = f · opacity · amount`。
2. **`amount` 语义重定义**(架构 §1.4 裁决 #2,选方案 A):从「曝光附加量
   (`exposure + amount*0.5`)」改为「蒙版强度倍率(`f_eff = f · amount/100`,负值反向)」。

存量含蒙版照片因此会以新口径重新解释——观感可能改变。架构要求:**告知用户 + 修复
存量失效数据,无静默改观感**。本报告即量化证据。

## 2. ① 差异报告:3,640 张总体的 50 张抽样

### 2.1 总体圈定(不编造,sidecar 真相源逐张判定)

- `develop_settings` 派生缓存未全量回填(mask_count 仅已打开过的照片有值),
  `library.queryPhotos({hasMasks:true})` 会漏报——因此按 `has_edits=1`(4,351 张)
  **全量读 sidecar**(`xmp.read` × 4,351)逐张判定,得含蒙版总体 **3,640 张**
  (增量 PRD 中的「约 3,639」为规划值;本报告数字为 mocklib 落盘 sidecar 的实测值)。
- 抽样:按 capturedAt 升序等距确定性取样 50 张(同一库每次跑同一组)。
- 50 张中 1 张(photoId=260)原片文件缺失(mock 设计的 421 张 missing 照片之一,
  `P0000260.dng`),渲染失败**如实计入 failed=1**,未替换、未编造;有效样本 49 张。

### 2.2 方法论

- **旧解释** = 054eb2c~1 v2 composite 的 CPU 逐字镜像(`app/src/modules/develop/webgl/ops/legacyMaskV2.ts`,
  档案镜像,不入渲染管线):前 6 槽 enabled 蒙版、`amount` 混入曝光公式、tint/dehaze
  静默丢弃、combine 忽略、display 域末道施加——施加在「无蒙版引擎渲染结果」上
  (= 旧管线 composite 位于 sRGB 编码之后的末道位置)。
- **新解释** = `develop.render`(v3 mask pass,与导出完全同一代码路径)。
- 比对:longEdge=320,逐像素 8bit RGB LSB;可见门槛 mean≥0.5 或 max>3(同 §10 parity 口径)。

### 2.3 数字(m2-visual-diff.json 实测)

|---|---|
| population(含蒙版总体) | **3,640** |

「蒙版从 inert→生效 / 语义重定义」两大静默失效面,现在有量化数字与逐张明细。

| 字段 | 值 | 说明 |

### 5.2 成因与修复策略(报告诚实性说明)

stale 13,842 行**全部是 has_edits=0 的未编辑照片**:importer 曾对每张导入照片无条件写
`sidecar_path = replaceExtension(finalPath, "xmp")`(engine/src/import/importer.cpp:199),
无论 .xmp 是否存在——未编辑照片的 sidecar_path 从一开始就是虚构值(无参数可丢)。

migration 005 对失效行的三路分流(架构 §3.3.1 末小节):

- **a) 重算命中**:重算路径(`sidecarPathFor(file_path)` 同口径,replaceExtension .xmp)
  存在 → UPDATE 路径 + mtime。本库 0 行。
- **b) 归零**:重算不存在且 has_edits=0 → 本来无 sidecar,清除虚构路径
  (可随时重算,不属于「清空用户线索」)。本库 13,842 行。
- **c) 不可恢复**:重算不存在且 has_edits=1(sidecar 真丢失)→ 逐条进
  `unrecoverable[]`({photoId, filePath, triedSidecar}),保留原路径不清空、不静默。
  本库 0 行。

**验收「修复后失效行数 == 0」达成**:独立 SQL + 文件系统复核,修复后
「sidecar_path 非空且文件不存在」= **0 行**(剩 4,351 行非空路径全部真实存在)。

**代码侧防复发**(importer.cpp):仅当 sidecar 文件真实存在才登记路径;未编辑照片保持
空(读取路径对空值有 `sidecarPathFor` 重算兜底,xmp_service.cpp:354),首次编辑时由
updateSidecar 写入真实路径——否则版本门控后新导入会重新积累虚构路径。

repaired=0、unrecoverable 逐条一致(不动点);残余失效行全部在 unrecoverable 名单
